## ② 5번 단계 세부 — 8요소 정의

> **판정 기준(개정)**: "문장에 없냐"가 아니라 "요청 수행에 보완이 필요하냐"로 판정.
> 요소가 없어도 그 작업에 불필요하면 0. 상세는 [`LABELING_CRITERIA.md`](LABELING_CRITERIA.md).

| 요소 | 설명 |
|------|------|
| Task | 무엇을 요청하는지 (요약/번역/작성 등) |
| Audience | 대상·독자·수신자 |
| Context | 배경·상황 정보 |
| Format | 출력 형식 (표, 목록 등) |
| Tone | 어조·말투 |
| Length | 글자 수·줄 수 |
| Constraint | 제약 조건 |
| Example | 예시·참고자료·형식 |

**업무유형 7종** (내부문서 필요 여부):

| 유형 | 설명 | 내부문서 |
|------|------|:--------:|
| email | 일반 이메일 | 아니오 |
| report | 일반 보고서 | 아니오 |
| report_internal | 내규 참고 보고서 | **예** |
| notice | 일반 공지 | 아니오 |
| notice_internal | 정책 관련 공지 | **예** |
| support | 고객 응대 | 아니오 |
| application | 신청서 (휴가/경비/구매) | **예 (항상)** |

> 검색 규칙: 업무유형에 `_internal`이 붙거나 `application`이면 13번(내부검색) 실행.

## 목업에서의 구현 상태

이 레포에서 각 단계는 아래처럼 구현된다:

- **실제 구현** (mock 아님): 1,2,3,6,8,9,10,11,12,16 — 규칙·UI·로직이라 목업도 진짜로 동작

mock은 실제와 **같은 입출력 형식**으로 가짜 응답을 준다. 교체 시 형식만 맞추면
나머지 파이프라인은 그대로 작동한다. → [`MOCK_GUIDE.md`](MOCK_GUIDE.md)
